# EV6 SPAS2 방향지시등 — 차량 시험 전 검증 기준 (2026-11-25)

> **상태: NO-GO / 차량에서 SPAS2 송신 금지.** 이 문서는 차내 실행용 명령이나 ECU 통신 차단 방법이 아니다.
> 기록된 값과 실험용 가정을 분리한다. 하드웨어·실제 ECU 검증이 끝나지 않았다.

## 1. 사용자 EV6 실제 기록에서 확인된 사실

| 증거 | 현재 결과 | 한계 |
| --- | --- | --- |
| rlog(6), 순정 자동주차 좌측 | SPAS2 0x16A, BLINKER_CONTROL=3, 램프 점등 | 순정 ECU 동작 |
| rlog(7), 순정 자동주차 우측 | SPAS2 0x16A, BLINKER_CONTROL=4, 램프 점등 | 순정 ECU 동작 |
| rlog(9), P단 정차 | 순정 0x165/0x16A 약 50Hz, 방향 명령 0 | 외부 제어권 미확인 |
| rlog(6/7/9) CRC 검증 | SPAS1 9,238개 + SPAS2 9,239개, 실패 0 | 전부 순정 수신 데이터 |
| rlog(8), 0x3C1 테스트 | 호스트 송신 3회 기록, 램프 점등 없음 | BCM 수락 여부 확인 불가 |
| PR #41 | SPAS2 수동 진단 완료, 실제 송신 0 | 송신 가능 여부와 무관 |

**중요:** 기존 기록에는 외부 장치가 요청한 0x7B1 진단 세션이 없다. 0x7B9 응답 부재만으로 '지원한다' 또는 '지원하지 않는다'고 판단할 수 없다.

PR #46은 기존 0x3C1 송신 허용 조건을 **더 엄격하게** 할 뿐이며 새로운 송신 ID를 추가하지 않는다.

## 3. 반드시 충족해야 할 실측 관문

1. **시험 대상 확인 (미완료):** 사용자 EV6 사양과 일치하는 주차보조 ECU의 정확한 부품번호, 펌웨어, 진단 주소 및 게이트웨이 경로를 정식 자료로 확인. 다른 차종의 0x7B1/0x7B9 정보를 EV6 확정 정보로 사용하지 않는다.
2. **독립된 실험 장비 (미완료):** 차량과 분리된 ECU/CAN-FD 벤치, 사양 확인된 전원·퓨즈, 종단·접지·배선 검증, 별도 CAN-FD 분석기와 오류/수신 누락 계측, 전원 차단 장치, 실제 ECU 전문가.
3. **무송신 기준 기록 (미완료):** 정상 전원 조건에서 SPAS1/2 원본과 카운터·CRC·주기·CAN 컨트롤러 오류 상태 확보.
4. **실제 진단 응답 (미완료):** 격리 벤치에서 실제 ECU가 0x7B1 요청에 대해 독립 분석기에 기록되는 정상 0x7B9 응답을 내는지 검증. 호스트의 송신 에코는 ECU 응답이 아니다.
5. **순정 송신 중단 (미완료):** 응답 이후 원래 0x165/0x16A가 모두 멈춘 것을 시간 동기화된 원본 버스 기록과 독립 오류 계측으로 확인. 조용한 버스는 단선/필터/로거 오류일 수도 있다.
6. **복구 (미완료):** 기한 내 정상 통신 복귀와 두 SPAS 메시지의 카운터·CRC·주기 복원 검증. 실패할 경우 그 시도의 결과를 안전으로 분류하지 않는다.
7. **panda 안전성 (미완료):** PR #46 C 코드 빌드/정적 분석/안전 테스트, 실차 이전 독립 검토. 실제 SPAS2 송신용 새 정책은 아직 존재하지 않는다. **기존 0x3C1 정책과 혼동 금지.**
8. **차량 실험 프로토콜 승인 (미완료):** 별도 안전성 검토 후 P단·정차·풋브레이크·무가속·주변 통제, 장애 발생 시 원상복구 및 DTC 확인 계획. 운행 중 테스트 불가.

하나라도 미충족이면 **NO-GO**. 가상 벤치에서 41개 테스트가 통과했다는 사실은 위 미충족 항목을 통과시켜 주지 않는다.

## 4. 지금 하지 말아야 할 것

- 실제 EV6에서 진단 통신 차단이나 0x165/0x16A 중복 송신을 시도하지 않는다.
- 순정 자동주차가 이미 작동 중이라는 이유로 외부 장치에 같은 ID를 추가 송신하지 않는다.
- panda 안전 모델의 TX 제한을 우회하지 않는다.
- PR #43/#44/#45/#46을 차량에 무조건 병합하지 않는다. 소프트웨어 로그 검증과 차량 동작 검증은 다르다.

## 5. 승인된 격리 벤치 기록이 준비될 때의 분석 도구

벤치 기록은 PR #45 문서에 정의된 JSONL로 내보낸다. 모든 레코드의 `ms`, `bus`, `direction`, CAN 주소·데이터가 필요하며 건강 상태 레코드는 전체 오류/누락 카운터와 상태 플래그가 필수다.

```bash
python -m unittest discover -s tools/signal_analysis -p test_ev6_bench_trace_validator.py -v
python tools/signal_analysis/ev6_bench_trace_validator.py isolated_bench_capture.jsonl --out isolated_verdict.json
```

여기서 `ISOLATED_BENCH_HANDOFF_AND_RESTORE_OBSERVED`라고 출력돼도 **제공한 캡처 파일의 형식/상태 판정에 한정**된다. 독립 계측 기록과 실제 ECU 출처에 대한 사람의 확인이 추가되어야 한다. 코드 자체는 실제 CAN 메시지를 송신하지 않는다.

## 6. 현재 결정

**소프트웨어 단계의 준비는 정리됨. 실제 차량 점등 시험 개시 = 불가.** 다음 새 증거는 **격리된 실제 EV6-compatible APRK ECU**의 응답·송신 중단·복구 캡처이며, 그 전에는 추가 코딩만으로 안전성을 입증할 수 없다.
