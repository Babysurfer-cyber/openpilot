# EV6 순정 SPAS2 방향 요청과 램프 점멸 피드백 — 수신 전용 검증

**분석 대상:** 사용자가 앞서 제공한 2022 EV6 순정 자동주차
`extract_6.csv` (좌측), `extract_7.csv` (우측).
**도구:** `ev6_spas_lamp_cadence.py`.
**방식:** 저장된 CSV의 bus0 SPAS2 `0x16A`와 방향 램프 상태 `0x413`
만 읽는다. 외부 CAN/UDS 명령을 생성·송신하지 않는다.

**관측 사실:** `BLINKER_CONTROL=3/4`가 유지되는 동안
실제 램프 상태는 반복해서 ON/OFF가 된다. 이때 raw byte7/18 조합이
8초 이상 **같아도** 24~25번의 점멸 상태 변화가 기록됐다.
따라서 이 두 raw 바이트의 모든 변화가 *매번 램프 점멸을 켜고
끄는 직접 트리거*라는 해석은 자료와 일치하지 않는다.
하지만 두 값이 활성화·주차 상태·다른 시스템 동작에 필요한지
여부는 이 관찰만으로 판정하지 못한다.

## 기존 '점등 지연' 숫자의 정확한 의미

이전 문서에 있는 **좌측 29.4ms, 우측 10.2ms**는 SPAS2 방향
명령 시작 후 **최초로 램프 ON이 기록된 0x413 수신 표본 시각**이다.
0x413 자체는 이산적으로 기록되므로 물리 램프의 실제 점등
시점과 동일하다고 할 수 없다.

- 좌측: 방향 요청 시작 **+9.2ms에 OFF 표본**,
  **+29.4ms에 ON 표본**. 실제 상태 변화는 그 두 표본의
  **20.2ms 관측 구간 내**에 있었다고 해석할 수 있다
  (포착된 ON/OFF 상태가 실제 물리 상태를 반영한다는 전제).
- 우측: 방향 요청 시작 **-71.9ms에 OFF 표본**,
  **+10.2ms에 ON 표본**. 실제 변화는 **82.1ms 관측 구간 내**였으며,
  그 구간이 방향 요청 전후를 모두 포함한다.
  따라서 우측에서 실제 물리 램프가 방향 요청 *이후* 켜졌다는
  인과관계는 이 자료만으로 확정할 수 없다.
- `0x413`의 중앙값 표본 간격보다 더 세밀한 물리적
  지연 시간을 추정하지 않는다. 표본 누락이나 지연도 불확실성이다.

## 재현 및 안전 한계

기존 로컬 57개 Python 오프라인 테스트와 새 12개 회귀시험
총 **69/69 통과**. `py_compile`과 네 개 수신 전용 분석 모듈의
CAN 송신 인터페이스 부재 AST 검사 통과.

~~~bash
python opendbc_repo/opendbc/car/hyundai/ev6_spas_lamp_cadence.py \
  --left /path/to/extract_6.csv \
  --right /path/to/extract_7.csv \
  --output cadence_report.json
~~~

**이 결과는 기록 당시 순정 ECU에 관한 관찰이다.**
콤마3의 명령을 BCM이 받아들이는지, ECU 인계 응답이 존재하는지,
실제 외부 송신 시 안전한지는 판정하지 못한다. 이미 진행된
합성 회귀시험과 로그 재생을 반복해도 이 하드웨어 검증 공백은
메워지지 않는다. 원본 CSV는 GitHub PR에 추가하지 않았다.
