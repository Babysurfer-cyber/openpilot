# 현대 CAN-FD 코너레이더와 궤적 기반 차량 인식

원본은 `ajouatom/openpilot`의 `carrot-wip`, 커밋
`162da468cc4157f9b18daa4f6ac85438f51719ef`이다. 원본 `radar_motion`의
궤적 기반 cut-in/cut-out, 정지차 매칭 및 추종 대상 선정과 종방향 제어 연결을 이식했다.
이전 0x180 이식에서 사용한 기존 브랜치의 끼어들기 조건 대신, 지원 차량에서는
원본 `DPathRadarController`가 `leadOne`과 보조 `leadTwo`를 계산한다.

## 활성화와 자동 감지

현대/기아 CAN-FD 차량에서 아래 메시지 묶음을 ACAN에서 감지한다.

| 종류 | 감지 조건 | 최대 물체 수 |
|---|---|---:|
| 0x180 | 0x180~0x184의 다섯 메시지가 모두 32바이트 | 10 |
| 0x235 | 0x235~0x248의 스무 메시지가 모두 32바이트 | 20 |

차량에서 감지된 묶음의 파서만 활성화한다. 두 묶음이 모두 존재하면 둘 다 처리하며,
출처와 추적 ID를 분리한다. 다른 메시지가 계속 수신되더라도 누락된 주소의 물체는
약 0.5초 뒤 제거한다. DBC는 일반 빌드에서 자동 생성된다.

시작 설정의 **코너레이더 트랙**(`EnableCornerRadar`)을 변경한 뒤 재시작한다.

| 값 | 지원 차량 | 지원 묶음이 감지되지 않은 차량 |
|---|---|---|
| 0 | 기존 브랜치의 레이더 처리 | 기존 처리 |
| 1 | 원본 궤적·정지차 처리 | 기존 처리 |
| 2 | 1과 같은 원본 처리 | 기존 후측방 거리 기반 끼어들기 처리 |

지원 차량의 2번 설정에서는 이전 거리 기반 처리와 원본 궤적 처리를 중복 실행하지 않는다.
지원 CAN-FD 묶음이 없거나 설정이 꺼져 있으면 기존 `RadarD`를 사용한다.

`EnableRadarTracks`는 전방 레이더/SCC 데이터의 사용 방식을 계속 결정한다.
원본 경로에서 1은 전방 트랙, 2는 전방 트랙과 저속 SCC, 3은 전방 매칭 뒤 SCC
보조 사용을 포함한다. 0/-1은 SCC 중심, -2는 주 추종 대상에 레이더를 사용하지 않는
설정이다. 실제 전방 트랙이 없는 차량에서 이 값을 올리면 트랙이 생기는 것은 아니다.
cut-out과 전방 레이더를 활용하는 정지차 판정에는 정상 수신되는 전방 트랙이 필요하다.

## 이식된 판정과 제어

- **Cut-in:** 경로 기준 물체 이동 이력으로 진입 시점과 신뢰도를 계산한다.
  센서 간 같은 차량 연결, 슬롯 이동, 진입 철회, 옆차 추월, 곡선 및 좌우 흔들림에
  대한 원본 조건을 유지한다. 확인된 후보는 보조 `leadTwo`와 `leadsCutIn`으로 전달한다.
  기존 경로의 60km/h 이하 보조 차량 취소 조건은 이 원본 처리에 적용하지 않는다.
- **조기 감속:** 확인 전 강한 끼어들기 위험을 `leadCutInRisk`로 전달하고, 플래너에서
  신뢰도·접근 속도에 따른 제한된 감속 상한을 적용한다. 원본 상한은 -0.25~-0.65m/s²이며,
  한 계획 주기에서 목표 가속도 변화도 제한한다.
- **Cut-out:** 비전으로 확인한 앞차가 빠져나가는 궤적을 예측해
  `cutOutTime`/`cutOutConfidence`를 전달한다. ACC의 MPC는 예상 차체 이탈 이후의
  차간거리 제약만 제한적으로 완화한다. 현재 장애물과 FCW용 실제 궤적은 유지한다.
  완화량은 최대 0.5초 차간거리 또는 8m이고, 이탈 이후에도 0.3초 여유를 둔다.
  가속 페달, 정지·리셋, 강제 감속, 차선 변경, 오래되거나 유효하지 않은 레이더 상태에서는
  이 완화를 사용하지 않는다.
- **정지차 인식:** 원본의 정지차 위치·속도 이력, 비전 지지, 전방/코너 센서의 같은 차량
  확인, 정지 직전 차선 내 코너 물체 및 정지차 추종 대상 인계 조건을 포함한다.
  정지한 레이더 반사체를 모두 추종 대상으로 채택하는 방식은 아니다.

새 궤적 처리의 생산 감도는 원본처럼 3으로 고정한다. 기존 `RadarLatFactor`의
차선 진입 확률 조건을 새 검출기에 다시 적용하지 않는다.

## 데이터와 화면

센서 출처 `frontRadar`/`scc`/`corner180`/`corner235`와 실제 전방 레이더의 `trackState`를
전달한다. 그룹2의 `VALID`와 구형 레이더의 `STATE`를 사용하며, 상태가 없는 그룹1에
확정 상태를 임의로 부여하지 않는다. cut-out 등 상태를 요구하는 조건은 이를 따른다.

모델 노출 시각과 레이더 발행 시각을 정렬하고, 코너 센서의 0.05초 측정 지연을 보정한다.
센서 시각 차이 0.15초 제한과 `livePose` 회전율의 좌표 변환을 사용한다.
유효하지 않거나 오래된 필수 입력에서는 판정 이력을 초기화한다.

`ShowRadarInfo`를 켜면 두 종류 코너 트랙을 보라색 `C` 표시로 구분한다.
도로 투영은 원본처럼 전방 2.5m 초과 물체에 적용한다. 바로 옆에 있어 종방향 거리가
0으로 잘린 물체는 데이터에는 남아도 도로 위로 투영하지 않는다.

기존 메시지 번호와의 호환성을 위해 `LeadData.radarSource @18`은 유지하고,
`cutOutTime @19`, `cutOutConfidence @20`을 추가했다. `leadCutInRisk @22`와
`RadarPoint.trackState @11`도 추가했다.

## 검증 범위

최종 합동 테스트는 1,172개와 하위 사례 3개가 통과했다. 원본 합성 회귀 1,016개는
Python 경로와 실제로 컴파일한 Cython 경로에서 각각 통과했다.

원본의 궤적·정지차·센서 정합 합성 회귀 테스트와 대상 브랜치의 자동 감지·CAN 바이트
디코딩·입력 소실·래퍼·플래너/MPC 연결 테스트를 실행한다. Cython 연산 가속 모듈과
Python 대체 구현을 모두 검사한다. 가속 모듈은 일반 SCons 빌드에 연결되어 있다.

로컬 테스트에서는 실제 CAN 파서, DBC, Cap'n Proto 및 궤적 알고리즘을 사용한다.
누락된 Params/msgq 네이티브 모듈과 실제 MPC 솔버는 테스트 실행기 또는 테스트 더블로
대체되는 범위가 있다. 전체 차량 빌드, 실제 로그 재생과 실차 인식률·제동 검증은 별도다.
0x430/0x440의 미검증 레이더 디코더와 Bosch/다른 전방 레이더 계열 확장은 포함하지 않는다.
