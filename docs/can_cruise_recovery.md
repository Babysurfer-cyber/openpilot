# CAN 오류 후 크루즈 복구

현대·기아 CAN-FD 차량에서 오픈파일럿이 종방향 제어를 하는 경우에 적용한다.
시작 설정의 `CAN 오류 후 크루즈 복구`(`CanErrorCruiseResume`)는 기본값 1이며,
0으로 끌 수 있다. 일반 `AutoCruiseControl=0` 설정과 독립적이다.

크루즈가 실제로 작동하다 `canError`로 해제되고, 차량 CAN 전체 단절은 아닌
경우만 복구를 예약한다. 초기 부팅·일반 해제·레이더만의 CAN 오류에서는
크루즈를 새로 켜지 않는다. 조향 활성 상태가 유지되는 주행 중에만 적용한다.

복구 조건은 다음과 같다.

- CAN과 필수 서비스가 정상이고, `selfdriveState.engageable` 및 기존 진입
  조건이 허용해야 한다. 이벤트 메시지의 정상적인 변경 발행은 고정 1Hz
  평균 주파수 검사에 넣지 않고, 유효성·수신 시각·진입 금지 여부를 확인한다.
- Panda·모델·레이더·종방향 계획·제어 상태는 오류 이후 새로 수신돼야 한다.
  데이터 나이도 확인하며, 모든 조건이 0.2초 연속 유지돼야 한다.
- 예약은 최대 3초다. 브레이크·가속·회생제동·조향 개입, 버튼 입력 및 누른
  상태 유지, 조향 해제, 기어·문·안전벨트 등 조건 변화가 있으면 폐기한다.
  새 CRUISE/SPEED 명령도 자동 복구보다 우선한다.

요청은 가상 `+` 버튼이 아니라 기존 `activateCruise → buttonEnable →
StateMachine` 경로로 한 번만 전달한다. 정상 상태에서 마지막으로 확인한
설정 속도를 복원하며, 0·미설정·비정상 속도는 복구 목표로 사용하지 않는다.
같은 프레임에 새로운 진입 금지 사유가 생기면 기존 상태 머신이 거부한다.

자동 요청 후에는 재발하는 오류에 계속 재요청하지 않는다. 운전자가 새로
활성화 버튼을 조작하고 실제 활성화된 뒤에만 다음 자동 복구를 허용한다.
원본 버튼 메시지 자체가 유실된 동안의 관측되지 않은 조작을 복원하는
기능은 아니며, CAN 수신 중단이나 SPI 오류의 원인을 고치는 변경도 아니다.

기존의 원인 구분 없는 0.5초 가상 `+` 입력은 제거했다. 요청 시에는
`CAN recovery requested: ... km/h`를 기록한다.

## 검증

실제 크루즈 보조 코드·차량 이벤트·상태 머신을 포함한 호스트 검사 76건을
통과했다. 제공된 EV6 로그 입력을 재생했을 때, 오류 약 0.967초 후 이전
설정 속도 60km/h로 요청 한 번이 생성됐고 설정 OFF에서는 생성되지 않았다.
이는 기록된 입력에 대한 검증이며 실제 차량 송신·재활성화 검증은 아니다.
선택 회귀 검사 1,226건과 별도 상태 머신 검사 7건도 통과했다. 기존 BSD
검사의 최대 거리 기대값은 사용자 변경인 15m에 맞췄으며, BSD 동작은 수정하지
않았다. 호스트에 없는 Hypothesis·parameterized 의존 검사와 장치 전체
빌드·실차 주행은 검증 범위에 포함하지 않았다.
