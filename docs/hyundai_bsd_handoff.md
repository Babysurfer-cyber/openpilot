# EV6 추월 중 BSD 조기 해제 보완

대상 증상은 2022년식 EV6에서 내가 상대 차량을 추월할 때 B필러 부근에서
BSD 표시가 풀리는 현상이다. 실제 차량 로그는 아직 없으며, 아래 조건은 코드와
합성 CAN 입력으로 재현한 조기 해제 조건이다. 실제 B필러 위치와 거리 신호의
대응 관계까지 확인했다는 뜻은 아니다.

## 재현한 문제와 수정

기존 로직은 전방에서 처음 감지한 물체가 후방 감지로 넘어가면 `L_source`/`R_source`를
`front`에서 `rear`로 덮어썼다. 이후 후방 거리가 5m 이상이며 증가하면, 새로 설정한
유지 타이머를 같은 프레임에서 취소했다. '내가 추월할 때는 후방 취소를 무시'한다는
기존 정책이 감지 전환으로 사라진 것이다.

이제 경고가 유지되는 동안 최초 전방/후방 진입 구분을 보존한다. LF→LR 또는 RF→RR
전환은 별도 추월로 취급하지 않는다. LF 4→3m, 일시 소실, LR 2→4.95→5.05m인
합성 입력에서 경고가 중간에 꺼지지 않고, 유지 시간이 끝나면 정상적으로 해제된다.
반대 방향 추월의 전방 이탈 해제와 좌우 독립 처리는 유지한다.

## 입력 처리 보완

- 카메라 쪽 순정 `ADRV_0x1ea`/`CCNC_0x162`의 같은 코너 거리·횡거리 쌍을 사용한다.
  가까운 물체를 먼 값과 `max()`로 합쳐 놓치지 않도록 신선한 가까운 입력을 선택한다.
- 실제 메시지 수신 시각으로 속도를 계산한다. 느린 메시지의 캐시를 100Hz의 새 측정처럼
  반복해서 속도 이력에 추가하지 않는다. 약 0.1초의 이력과 기존 1.5m 거리 튐 필터를 유지한다.
- 300ms보다 오래된 입력을 새 물체 감지로 사용하지 않는다. 수신이 끊기면 기존 유지 규칙을
  한 번 적용하며, 캐시 때문에 타이머가 영구 갱신되지 않는다.
- 초기 탐색 구간이 끝난 뒤 처음 수신되는 BSD 메시지도 등록한다. 선택 메시지 누락 자체는
  전체 CAN 오류를 만들지 않으며, 수신된 데이터의 체크섬·카운터 검사는 유지한다.
- 순정 BSD는 ECAN/CAM의 신선한 경고를 확인하고 보완 경고와 OR로 합친다. 보완 로직의
  만료·취소가 순정 경고를 끄지 않는다. CAM에서만 들어오는 순정 BSD도 감지한다.
- 계기판 전달을 위해 자체 송신하는 ECAN 거리 메시지는 보완 입력으로 다시 읽지 않는다.

기존 전방 가변 경고 영역(기본 6m, 접근 시 최대 12m, 멀어질 때 최소 2m), 후방 5m,
4.5초 기반 유지와 전방 이탈 `6/상대속도`, 후방 이탈 3초 유지 수식은 보존했다.
타이머는 호출 횟수 대신 실제 수신 시각의 경과 시간을 사용한다.

## 적용 범위와 검증

이 수정은 CAN-FD `CarState`의 표시 거리 기반 BSD 보완에 적용된다. 0x180/0x235
물체 트랙의 DPath 선택이나 cut-in/out 판정을 바꾸는 작업은 아니다. BSD 보완은
기존 `RadarD`와 새 DPath 경로 모두에서 CarState를 통해 실행된다.

회귀 테스트는 좌우 전방→소실→후방 인계, 반대 방향 추월, 나란히 주행, 10/20/100Hz
입력, 가까운/먼 입력 충돌, 늦은 최초 수신, 수신 중단, 순정 BSD 합성·버스 변경과
실제 EV6 `CarState.update()` 연결을 확인한다. 실제 CANParser/CANPacker와 Cap'n Proto를
사용하며, 로컬의 Params/msgq 네이티브 import는 외부 테스트 실행기로 대체한다.
BSD 전용 46개 테스트와 기존 레이더·제어 테스트를 합친 1,218개 및 하위 사례 3개가 통과했다.
전체 차량 빌드와 해당 EV6의 실차 재확인은 별도다.
