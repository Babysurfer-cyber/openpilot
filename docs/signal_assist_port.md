# carrot-wip 신호 인식 보조 이식

대상은 `Babysurfer-cyber/openpilot`의 `ms-xy-radar3`이며,
`33b1ac32b26f427b4a77b1f5635570b48e00810b`를 기준으로 추가했습니다.
원본은 `ajouatom/openpilot`의 `carrot-wip`,
`162da468cc4157f9b18daa4f6ac85438f51719ef`입니다.

## 사용 설정

업데이트 후 전체 재부팅하여 새 Params 키, 메시지 스키마, 카메라 바인딩과
화면 코드를 다시 빌드해야 합니다. 설정에서 **신호보조 모드 (시험)**을 선택합니다.

| 값 | 동작 |
|---|---|
| 0 | 추가 신호 인식·표시·제어 끔. 기본값이며 기존 신호 판단을 사용합니다. |
| 1 | 카메라 신호 검출·추적 표시, 알림, 정차 중 확인한 적색에 대한 출발 억제. |
| 2 | 1의 기능과 주행 중 완만한 감속 준비. 정차 후 출발 억제는 1과 같습니다. |

검출 표시는 종방향 제어가 비활성인 동안에도 동작합니다. 실제 보조 제어는
기존 신호감지·주행모드 제한을 따릅니다. 이 브랜치에서 신호감지가 꺼지는
일반/고속 모드와 `TrafficLightDetectMode=0`에서는 보조 제어도 하지 않습니다.
정지 전용 설정(1)을 녹색 출발로 덮어쓰지 않습니다. 조향각 20도 초과,
기어·차량 상태·입력 신선도 등 기존/추가 조건도 확인합니다.

별도 신호등 전용 신경망 모델을 받는 설정은 아닙니다. 원본의 기본 CPU 검출·추적
경로를 이식했습니다. 원본 저장소에 없는 선택적 신경망 ONNX 가중치는 포함하지
않았으며, 현재 주행 모델과 운전자 모니터링 모델을 교체하지 않습니다.

## 인식과 제어의 연결

- 원본 `SignalTracker`의 색상·램프 검증, 주간/야간 후보, 물체 추적과 시간적
  확인을 사용합니다. 정지 시 적색을 기억하고, 같은 물체/신호 그룹에서 확인한
  녹색 전환을 기존 신호 상태 판단에 연결합니다. 녹색 상자 하나만으로 출발하지
  않습니다. 알 수 없음이나 오래된 관측은 녹색 확인으로 취급하지 않습니다.
- 앞차가 기존 정지 판단의 추종 범위에 들어오면 기존 앞차 추종을 사용합니다.
  앞차가 있는 동안 신호 관련 알림을 억제하며 레이더 장애물은 계속 MPC에 남습니다.
- 모드 2의 감속 준비는 5km/h 초과, 82km/h 미만에서만 가능합니다. 두 추적 앞차
  중 하나라도 50m 이내이거나 거리가 유효하지 않으면 추가 준비 감속을 하지 않습니다.
  운전자 페달, 소프트홀드, 기존 정지 제어, 회전 중 등의 조건도 차단합니다.
- 최종 가속도 상한을 초당 0.25m/s²씩 내려 최대 약 -0.5m/s²의 완만한 감속을
  요청합니다. 기존의 더 강한 제동은 유지합니다. 이 준비 기능은 정지선 위치나
  완전 정지를 결정하지 않으며, 그 판단은 기존 모델/플래너가 맡습니다.
- 최신 내비 도로 분류가 고속도로/도시고속도로를 명시하면 신호 관련 제어를
  일시 중지합니다. 이 브랜치의 `carrotMan` 전송에 분류 유효성·수신 시각을
  추가했으며, 분류가 빠진 메시지의 기본값 0을 고속도로로 추정하지 않습니다.

신호가 어느 차로를 제어하는지의 판단에는 여전히 한계가 있습니다. 원본의 후보
선택과 시간적 확인을 추가한 것이며, 실차 인식률 향상 수치를 측정한 결과는 아닙니다.

## 화면

기존 빨강/초록 신호 아이콘을 유지하고 별도의 **신호보조** 표시를 추가합니다.

| 표시 | 의미 |
|---|---|
| 바깥 원 | 검출 색상. 빨강/초록/혼합(노랑)/알 수 없음(회색). |
| 안쪽 점 | 실제 보조 상태. 빨강=출발 억제, 노랑=감속 준비, 초록=확인된 녹색 전환. |
| 흐린 원·점선 상자·`~` | 최대 2초 전 결과를 화면에만 유지한 표시. 제어 입력으로 재사용하지 않습니다. |
| 일시정지 표시 | 최신 내비 도로 분류에 따른 신호 제어 중지. |
| `S숫자` 상자 | 신호 후보의 추적 번호. 차량 레이더의 보라색 `C숫자`와 다릅니다. |

상자는 실제 표시 중인 전방 카메라 프레임과 시각을 확인하여 그립니다. 광각 카메라
화면에는 전방 카메라 상자를 겹치지 않으며, 요약 원만 표시합니다.

## C3 구조에 맞춘 변경

- 원본 1344×760 OS04C10 카메라에 더해 C3의 1928×1208 AR0231 입력을 지원합니다.
  가로 기준 균일 축소와 세로 중앙 자르기를 사용하며, 검출·기하 판단·화면 표시가
  같은 좌표 변환을 사용합니다. 기하 계산의 초점거리도 실제 카메라 설정에 맞춰
  같은 비율로 변환합니다. 다른 해상도는 임의로 해석하지 않습니다.
- `livePose`를 플래너 구독에 추가하고, 원본과 다른 타임스탬프 구조를 이 브랜치의
  메시지 봉투 시각으로 맞췄습니다. 보정/자세/카메라 정보가 오래되거나 유효하지
  않으면 감속 준비를 허용하지 않습니다.
- 별도 `signalcolord` 프로세스는 모드 1/2와 주행 상태에서만 실행됩니다.
  CPU의 낮은 우선순위로 실행하며 OpenCV 내부 스레드는 1개, OpenCL은 끕니다.
  최대 20Hz와 한 CPU의 약 50% 사용 목표로 작업 간격을 조절합니다. 실차에서
  실제 처리 속도와 다른 프로세스에 미치는 영향은 별도 확인이 필요합니다.
- OpenCV가 없으면 활성화된 보조 프로세스에서만 고정 버전 4.11.0.86의 바이너리
  패키지를 기존 `pydeps`에 설치합니다. 최초 설치에는 인터넷이 필요할 수 있습니다.
  NumPy나 다른 시스템 의존성을 함께 업그레이드하지 않으며, 시간·재시도 횟수를
  제한합니다. 실패하면 보조 관측을 비우고 종료 반복을 방지합니다.
- 카메라 공유 버퍼가 변환 중 재사용됐는지 확인하기 위해 기존 C++ 프레임 번호
  getter를 Python에 읽기 전용으로 노출했습니다.

기존 코너레이더·radar_motion·BSD 로직, 가감속/커브/차간거리 튜닝은 교체하지
않았습니다. HDA 점검 경고와 관련해 앞서 분석한 자동 MAIN 송신 코드는 이번 이식의
수정 대상에 포함하지 않았습니다.

## 검증

기능 OFF 상태에서 이식 전 전체 `CarrotPlanner`와 현재 구현을 10,800프레임
비교했습니다. 주행모드, 신호감지 설정, 정지/추종 상태, 파라미터 갱신, 필터와
이벤트를 포함한 비교에서 출력이 일치했습니다.

신호 제어·관측·좌표 변환과 기존 레이더/BSD를 함께 검사한 Python 테스트
1,897개 및 하위 검사 3개, 추가 CPU 추적·분석 테스트 122개가 통과했습니다.
로컬 Python 실행기는 설치되지 않은
native Params/msgq 프로세스 인프라만 대체했으며 실제 cereal 스키마, CAN
패커/파서, 추적·판단 알고리즘은 사용했습니다. 최적화 솔버가 필요한 일부 통합
검사는 기록용 솔버로 생산 코드의 입력·출력 연결을 확인합니다.

새 Qt 관측 데이터 읽기·유효성 검사·화면 유지 상태 모듈을 실제 QtCore로
컴파일하여 9개 테스트의 140개 검사를 통과했습니다. 전체 UI 실행 파일의
빌드는 이 환경에서 수행하지 않았습니다.

실제 native msgq/VisionIPC와 Python 바인딩을 빌드하여 프레임 번호 읽기 및
공유 버퍼 재사용 검사를 포함한 7개 통신 테스트를 실행했습니다. 실제 VisionIPC
입력에서 NV12 변환, 원본 CPU 추적기, 출발 억제·감속 준비·표시 JSON 출력까지
합성 적색/녹색/미확정 영상으로 연결했습니다. 1344×760에서 90프레임 중
88개, 1928×1208에서 89프레임 중 87개의 관측을 처리했습니다. x86 시험 환경에
맞춰 CPU affinity, 로그 수집, 출력 경로만 조정했으며 검출기와 통신은 대체하지
않았습니다. 이 수치는 실제 도로에서의 검출 성능을 뜻하지 않습니다.

이 검사는 실차 폐루프 주행, 실제 카메라 영상에서의 오감지/미감지율, 기기 전체
빌드와 성능 검증을 대신하지 않습니다.
