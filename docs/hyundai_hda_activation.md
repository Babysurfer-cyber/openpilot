# CAMERA SCC의 순정 HDA 재활성화 보호

코너레이더 수신을 유지하려는 자동 LFA·MAIN 입력과 합성 내비 메시지
`NEW_MSG_4B9`가 P단·정차·순정 HDA 오류 상태에서도 재시도되는 것을 제한한다.
순정 고장 팝업을 지우거나 진단 코드를 해제하는 변경은 아니다.

## 요청 조건

- 자동 재활성화는 정상 CAN, D단, 유한한 차량 속도, 수신된 순정 HDA 상태를
  요구한다. `HDA_OptUsmSta=7`, `HDA_InfoPUDis=4` 또는 수신된
  `CCNC_0x162.FAULT_HDA`가 0이 아니면 요청하지 않는다.
- 자동 LFA와 MAIN·주행 SET은 브레이크를 밟지 않고 3m/s를 초과해 움직일 때
  기존 송신 주기로 요청한다. 운전자가 버튼을 누르면 자동 입력을 추가하지 않는다.
- 정상 정차 후 재출발 SET에는 위의 3m/s 제한을 적용하지 않는다. 기존 제어 활성,
  순정 MAIN·ACC 상태, 정차 해제 요청 조건과 정상 CAN·D단·HDA 상태,
  브레이크 및 운전자 버튼 조건을 확인한다.
- 합성 `0x4B9`는 정상 주행 중 순정 HDA가 비활성이고 코너레이더 기능이 켜져 있을
  때만 보조 수단으로 사용한다. 실제 차량 내비의 `navi_segment_4b9`를 수신했다면
  합성 메시지를 보내지 않는다. 순정 내비의 모두 FF인 메시지도 임의로 덮어쓰지 않는다.

순정 `HDA_InfoPUDis`, `HDA_OptUsmSta`, `FAULT_HDA` 값과 기존 계기판 경고는
보존한다. 기존 물리 LFA 입력 처리, 코너레이더 디코딩·끼어들기 판정과
차량 조향·가감속 계산은 바꾸지 않는다.

## 검증과 한계

실제 CAN 패커·파서로 기어·정차·브레이크·CAN·HDA 오류·입력 수치 조건,
정상 주행의 기존 송신 주기, 정차 후 재출발, 운전자 버튼, 순정 내비 존재,
고장 팝업·원본 보존과 체크섬을 검사한다.

오류가 이미 발생한 뒤 시작하는 로그만으로 최초 발생 원인을 확정할 수는 없다.
기록된 입력에 새 송신 조건을 적용하는 검사는 호스트의 불필요한 재시도 차단을
확인하며, ECU 재현이나 실차에서 HDA 오류가 해결됐다는 검증을 대신하지 않는다.
