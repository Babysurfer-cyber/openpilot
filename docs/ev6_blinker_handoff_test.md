# EV6 정차 깜빡이 인계 시험

`HyundaiBlinkerTest`는 기본값 **0**인 시험 설정이다. 조향/가감속이나
차선 변경 기능과 연결하지 않는다. 대상은 기존형 `KIA_EV6`, CAN-FD,
`HyundaiCameraSCC > 0`, ECAN 버스 0인 이 브랜치의 배선 구성이다.
이 구성 이외에서는 주차보조 ECU 진단이나 시험 점등을 시작하지 않는다.
이미 실행 중인 새 코드에서는 설정 변경만으로 시험을 시작하고 끝낼 수
있으며, 시험마다 콤마를 재부팅하거나 주행 프로세스를 다시 시작할 필요가 없다.

## 설정과 사용

설정 → 시작 → **EV6 깜빡이 인계 시험 (정차 전용)**:

| 값 | 동작 |
| --- | --- |
| 0 | 시험 종료 → 주차보조 ECU 복구 확인 → Panda 일반 안전 모드 복귀 확인 |
| 1 | 왼쪽 최초 점등 요청 → 주차보조 ECU 복구 → 왼쪽 HOLD |
| 2 | 오른쪽 최초 점등 요청 → 주차보조 ECU 복구 → 오른쪽 HOLD |

1. 새 코드와 해당 Panda 펌웨어가 실행 중인 상태에서 1 또는 2를
   선택한다. 기본값은 0이다. 주행 중 값을 바꾸면 시험 시작 조건을
   기다리며, 대기 중인 선택 때문에 기존 주행 제어를 중단하지 않는다.
2. P단, 네 바퀴 속도 0, 가속 페달 0, 브레이크와 주차브레이크 적용,
   방향지시등 레버 중립, 비상등/방향지시등 꺼짐, 오픈파일럿 비활성을
   확인한다. 신선한 CAN 입력과 이 조건이 안정적으로 확인되어야
   임시 시험 모드로 전환한다.
3. 설정 설명의 **현재 상태**에 대기, 안전 모드 전환, 점등, ECU 복구,
   유지 및 중단 이유가 표시된다. 시험을 시작한 뒤에는 주행 제어가
   차단된다. 유지 중에도 정차와 브레이크 등 조건을 계속 유지한다.
4. 0으로 변경하면 HOLD를 해제하고 주차보조 ECU를 명시적으로 복구한다.
   ECU 응답과 순정 SPAS 재개를 확인한 뒤 Panda의 일반 안전 구성을
   복원하고 실제 읽기 결과까지 확인한다. 이 확인이 끝나야 일반 제어를
   다시 허용한다. 방향지시등 레버 조작, 움직임, 입력 끊김도 시험을
   중단시킨다. 복구가 확인되지 않으면 일반 모드로 강제 복귀하지 않는다.
5. 방향 변경이나 재시도는 **0으로 종료하고 복귀 완료 상태를 확인한 뒤**
   1 또는 2를 선택한다. 1에서 2로 바로 변경해 연속 시험하지 않는다.
   이 절차에는 수동 재부팅이 필요하지 않다.

이번 변경을 처음 설치할 때에는 Panda C/C++ 변경이 포함되므로 해당
펌웨어를 빌드·설치하고 새 프로세스를 실행해야 한다. 위의 재부팅 없는
설정 변경은 그 새 코드가 이미 실행 중인 경우에 해당한다.

## 처리 순서

- 기존 일반 `CarParams`와 정상 시작 초기화는 유지한다. 시험 설정을
  이유로 조향 튜닝, 종방향 제어 설정, 차량 인식 결과나 다른 프로세스가
  받는 `CarParams`를 바꾸지 않는다. `ENABLE_BLINKERS`도 상시 켜지 않는다.
- 정차 조건을 확인한 뒤 card와 pandad가 요청/확인 응답을 주고받으며
  Panda를 임시 시험 안전 모드로 전환한다. 실제 모드 확인 전에는 주차보조
  ECU 진단과 SPAS 명령을 보내지 않는다. 시험 중에는 일반 조향·가감속
  CAN 생성을 중단하며, Panda도 일반 주행 명령을 차단한다.
- 버스 0의 `0x7B1`에 `10 03`을 보내고 `0x7B9`의 `50 03` 응답을 기다린다.
  응답 없이는 통신 중지나 SPAS 명령을 보내지 않는다.
- `28 01 01`로 순정 주차보조 ECU의 일반 TX 중지를 요청한다.
  `68 01` 응답과 두 순정 SPAS 스트림의 100ms 침묵이 모두 필요하다.
- 마지막 CRC 정상 순정 SPAS1/2의 본문을 보존하고 카운터/CRC와
  SPAS2의 깜빡이 비트만 바꿔 최대 0.6초 요청한다. ADRV HOLD를 겹쳐
  보낸다. 해당 방향 CAN 점등 피드백이 오면 SPAS 송신을 즉시 끝낸다.
- `28 00 01`과 `10 01`로 정상 통신/기본 진단 세션 복귀를 명시적으로
  요청한다. `68 00`, `50 01` 응답 및 새 순정 중립 SPAS1/2 수신을 모두
  확인해야 유지 단계로 넘어간다. TesterPresent를 보내지 않는다.
- 유지 단계에서는 카메라 버스 2에서 받은 ADRV `0x1EA`의 원본을
  보존하고 LEFT/RIGHT_BLINK_HOLD 비트와 CRC만 바꾼다. 호스트 요청은
  Panda에 유지 방향을 전달하며, 실제 전달은 매 순정 프레임의 최신
  카운터와 본문을 사용한다. 정차 조건이
  유지되는 동안 계속 보낸다. 순정 SPAS나 점등 피드백이 끊기면 끝낸다.

각 0 → 1/2 요청에서 한 번만 시도한다. 복구는 실패 시 최대 3회 요청하며,
복구 응답 없이 성공으로 표시하지 않는다. 오류/종료 시 HOLD=0을 보낸다.
초기 요청/복구가 4초 안에 확인되지 않으면 비제로 HOLD를 유지하지 않는다.
SPAS 요청 간격은 최소 30ms, 유지 요청은 최소 60ms로 Panda의 20/50ms
제한보다 여유를 두었다. 해제 요청은 한 번 보내며 종료 후 반복 송신하지 않는다.

## Panda 제한

전용 safetyParam 비트 1024의 디버그 펌웨어 모드에서만 허용한다.
이 비트는 시험 중 Panda에 임시 적용하며, 일반 `CarParams.safetyConfigs`에
저장하거나 다른 프로세스에 배포하지 않는다.
TX 목록은 버스 0의 진단 `0x7B1/8`, SPAS `0x165/24`, `0x16A/32`,
ADRV `0x1EA/32`뿐이다. 일반 조향/가감속 명령은 거부한다.
진단 서비스·순서, CRC·카운터, 원본 본문 보존, 정차 입력 신선도,
SPAS 송신 시간과 주기를 C 코드가 별도로 검사한다. ADRV 요청은
최근 검증된 순정 프레임과 일치하는 본문/카운터만 허용하며, 호스트
프레임을 중복 송신하지 않는다. 비제로 HOLD가 허용되는 동안에만
전달할 순정 ADRV의 유지 비트를 치환한다. 입력 이상이나 150ms 동안
요청이 갱신되지 않으면 원본 그대로 전달한다. ECU 복구 요청은 입력이
사라져도 보낼 수 있다. `allOutput` 모드를 사용하지 않는다.

일반 설정 0의 안전 구성과 메시지 생성 경로는 유지한다. 시험 종료 시
단순히 설정값만 보고 일반 안전 모드를 복원하지 않는다. ECU 복구와
순정 CAN 재개를 확인한 뒤 정상 안전 구성 복원 요청을 보내고 Panda의
모드와 파라미터 읽기 결과가 일치해야 일반 제어를 다시 허용한다.

프로세스 사이의 전환 정보는 `HyundaiBlinkerTestSafetyRequest`와
`HyundaiBlinkerTestSafetyAck` 문자열 파라미터로 전달한다. 요청과 해당
확인 응답을 연결해 이전 응답을 새 전환의 성공으로 사용하지 않는다.
두 파라미터는 관리자 시작과 새 onroad 전환 때 초기화한다. 설정 화면의
`HyundaiBlinkerTestStatus`는 진행 상황 표시이며 안전 확인 응답을 대신하지
않는다. 입력이 사라지거나 ECU/안전 모드 복원이 확인되지 않으면 제어
차단을 유지한다. 통신 오류나 대기 시간 초과를 성공으로 처리하지 않는다.

통신 중지 요청(`28 01 01`)까지 전송한 경우에는 ECU 복구 응답과 새 순정
SPAS가 반드시 필요하다. 그 요청을 전혀 보내지 않은 진단 초기 실패는
복구 시도 종료 후 순정 트래픽이 계속 정상임을 확인해 일반 모드로
돌아갈 수 있다. 이를 ECU 복구 응답을 확인한 성공으로 표시하지 않는다.

이 변경에는 Panda 펌웨어와 pandad 변경이 포함되므로 Python 파일만
복사해서 시험할 수 없다.

## 검증 범위와 남은 실차 확인

실제 DBC의 CANPacker, Python 상태기계, 실제 C 안전 훅을 이용한
시뮬레이션으로 요청 순서, 양방향 인계, 지속 유지, 종료, 오류 중단과
메시지 범위를 검사한다. 런타임 안전 모드 전환, ECU 복구 후 일반 제어
재허용, 이전 확인 응답 거부, 차량 설정 보존과 기존 기능 회귀도 검사한다.
콤마 UI 전체 빌드나 EV6 실차 점등 시험을 대신하는 검증은 아니다.
이 개발 환경에는 SCons/ARM 툴체인이 없어 전체 콤마 UI와 Panda ARM
펌웨어 빌드는 수행하지 않았다. 실제 C 안전 훅의 호스트 빌드를 검증했다.
관련 Python/C 회귀 검사 1,903개와 하위 검사 18개가 통과했다. C++ 전환
검사 9개와 실제 `panda_safety.cc`/생성 Cap'n Proto를 사용한 호스트 검사
4개도 통과했다. 후자의 Params 저장소와 USB 호출은 대체체를 사용했으며
실제 장치 연결을 검증한 결과는 아니다.

**사용자 차량에서 물리적 최초 점등, ECU 복구 후 HOLD의 효과 및
주차보조 경고가 발생하지 않는지는 아직 확인하지 않았다.** CAN 점등
피드백과 순정 SPAS 재개는 주차센서·카메라 등 전체 기능의 정상 증명이
아니다. 진단 주소/세션이 해당 EV6에서 응답하지 않으면 시험은 중단된다.
콤마 전원 차단/프로세스 강제 종료 후 주차보조 ECU의 자동 복구 시간도
검증하지 않았다. 복구가 미확인되거나 경고가 남으면 주행 시험으로
이어가지 말고 시험을 종료하고 차량 상태를 확인해야 한다.

참고: 공개 joongyu `archive/carrot-wip-dev-20261016`의 Ioniq 5 PE 시험은
진단 응답이 없어 실제 SPAS 점등/ECU 중지/복구 단계에 도달하지 않았다.
이 구현은 그 시험의 실차 성공을 전제로 하지 않는 별도 시험 코드다.
