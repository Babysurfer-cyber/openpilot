# 새 레버 입력으로 이어가는 차선변경

기준 브랜치는 `Babysurfer-cyber/openpilot:ms-xy-radar3`의 `30ecfc1`이다.
joongyu01의 공개 개발 브랜치 보관본
[`archive/carrot-wip-dev-20261016`](https://github.com/joongyu01/openpilot/tree/archive/carrot-wip-dev-20261016)
(`765a5fd`)에서
[`05a2653`](https://github.com/joongyu01/openpilot/commit/05a2653097b8822cd5ee81be808ef58340a063db)
의 연속 요청 방식을 현재 C3 기반 구조에 맞춰 이식했다.

## 운전자 동작

- 기존 원터치 자동차선변경을 시작한다.
- 변경 도중 같은 방향 레버를 다시 툭 치고 놓으면 다음 변경을 하나 예약한다.
  경계 통과 전의 두 번째 원터치도 받는다. 경계 통과와 다음 차선 조건이
  확인되면 첫 변경의 완료·마무리 대기를 건너뛰고 다음 변경으로 연결한다.
- 램프가 계속 켜져 있어도 새 레버 입력은 별도로 인식한다. 새 입력 없이
  남은 깜빡임만으로 다음 자동 변경을 계속 반복하지 않는다.
- 세 번째 변경에는 새 변경 도중의 별도 원터치가 필요하다. 예약이 있는 동안
  여러 번 눌러도 다음 변경 하나만 예약하며, 여러 차선을 한꺼번에 쌓지 않는다.
- 별도 설정을 추가하지 않는다. 기존 `LaneChangeNeedTorque`,
  `LaneChangeBsd`, `LaneLineCheck`, `LaneChangeDelay` 설정을 사용한다.
  특히 토크 필요 설정이 1이면 다음 변경에도 토크 확인이 필요하다.

경계 통과는 모델 차선으로 추정한다. 변경 방향의 내부 차선이 차 중심에
1m 미만으로 접근했다가, 모델이 새 차선으로 번호를 바꾸며 최근접 거리보다
1.5m 이상 멀어지는 것을 본다. 양쪽 내부 차선의 유한값·순서·폭도 검사한다.
모델에서 이 통과를 확인하지 못하면 기존 모델 완료·마무리 절차를 따른다.
시간만으로 빠른 전환을 허용하지 않는다. 이는 실측 위치를 보장하는 검출기가 아니다.

원터치는 1단을 누른 뒤
중립으로 놓았을 때 확정한다. 1단을 오래 유지해도 놓기 전에는 자동 변경을
시작하지 않으므로, 완전 체결로 가는 중간 동작을 잘못 받지 않는다.
완전 체결은 턴 입력으로 분리하고 대기·예약·진행 중인 차선변경 상태와
소프트웨어 방향지시등 HOLD를 해제한다. 내비게이션 요청이 있어도 완전
체결 상태에서는 차선변경을 시작하지 않는다. 실제 턴 유도 출력은 기존
속도·도로·내비게이션 조건과 턴 유도 활성화·쿨다운 조건을 따른다.
모델 프레임 사이에 누르고 놓은 짧은 입력도
실제 레버 카운터가 정상 증가했다면 인식한다.

## 현재 브랜치에 맞춘 처리

`CarState`의 기존 UInt8 레버 카운터를 사용한다. 최초 표본은 기준값으로
저장하고, 한 방향의 정상 단일 증가만 새 입력으로 받는다. `255→0`은
정상 wrap이며, 점프·리셋·양쪽 동시 증가·무효 CAN은 이전 입력을 재생하지
않는다. 이때 아직 확정되지 않은 입력도 폐기한다.

빠른 전환은 모델의 경계 통과 관측에 더해 **현재 프레임**의 다음 차선과
도로 끝을 확인한다. 1초간 평균한 과거 차선 폭만으로 다음 차선을 가정하지
않는다. 기존 시작 조건을 공통으로 사용해 최신 BSD·측면 레이더 객체·차선
종류·사용자 토크 설정과 실제 같은 방향 깜빡이 피드백을 검사한다. BSD의
기존 1초 유지와 기존 수동/ATC 예외도 유지한다.

조건이 맞으면 `preLaneChange`를 한 모델 평가 주기 거쳐 새 변경을 시작한다.
이때 모델에 `none → laneChangeLeft/Right` 상승 에지를 새로 보내므로,
같은 방향 변경 요청이 첫 요청에 묻히지 않는다. 기존 약 1초의 마무리 복귀와
첫 변경의 낮은 모델 확률을 기다리는 과정은 생략한다. 전환 순간 차선 유도
복귀율은 0으로 유지하고, 새 장애물 때문에 막히면 점진적으로 복원한다.
새 시작 직전에도 모든 조건과 현재 차선 기하를 다시 검사한다.

첫 요청에서 남은 낮은 모델 확률이 다음 요청을 즉시 완료로 오판하지 않도록,
빠른 재시작 후 처음 0.5초는 완료 판정을 유예한다. 새 조향 요청은 바로 전달한다.
새 변경마다 경계 관측기를 초기화하므로 이전 통과 이력을 재사용하지 않는다.

예약 유효 시간은 **두 번째 원터치 확정부터 최대 약 5초**다. 시작 단계에서
대기한 시간도 포함하며, 빠른 전환이나 마무리 단계 진입으로 연장하지 않는다.
만료되면 HOLD와 예약을 해제한다. 나중에 BSD가 풀리거나 램프가 다시 켜져도
자동으로 재시작하지 않는다. 새 입력은 새 요청이 된다. 반대 입력·비상등·
완전 체결·반대 토크·횡제어 비활성·무효 입력·기존 변경 시간 제한에서도
예약을 버린다. 전환 중의 반대 입력을 반대 방향 자동 변경으로 재사용하지 않는다.

### 방향지시등 전달

- `ModelDataV2.MetaData`에 `laneChangeBlinkerHold @20`을 추가했다.
  기본값은 `none`이며 기존 필드 번호는 유지한다.
- 실제 `modeld`의 `DesireHelper.update` 결과를 이 필드로 발행한다.
- Hyundai의 기존 CAMERA SCC ADRV `0x1EA` 생성 경로에서 예약 방향을
  기존 유지 신호보다 우선한다. 좌우 HOLD를 동시에 켜지 않는다.
- 예약을 소비해 새 변경을 시작할 때도 새 변경의 경계 통과까지 HOLD를
  이어 초기 모델 확률 상승 구간에서 유지 신호가 끊기지 않게 한다.
  이후에는 기존 변경 유지 경로를 사용한다.
- 횡제어가 꺼지거나 모델이 무효·수신 중단 상태이면 HOLD를 해제한다.

정차용 `HyundaiBlinkerTest`와 연동하지 않는다. 이 기능은 주행 중 기존
방향지시등 유지 경로를 사용하며 주차보조 ECU 진단이나 SPAS 점등 요청을
추가하지 않는다. 원본의 Bluetooth, 강제 회전, 트레일러, 별도 차량 설정,
전체 차선변경 함수는 가져오지 않았다.

## 검증 범위

실제 Cap'n Proto와 CANPacker/Parser로 레버 카운터, 좌우 모델 차선,
FSM의 예약·완료·만료·취소, 사용자 조건 재검사, ADRV 출력과 직렬화를
검증한다. 기존 ATC 동작은 이식 전 helper와 같은 입력으로 비교한다.
최초 이식에서는 신규 검사 126개를 포함한 관련 회귀 검사 2,029개와
하위 검사 18개가 통과했다. 이후 완전 체결의 턴 분리와 원터치 해제
확정 검사 56개를 추가했고, 관련 회귀 검사 총 2,085개와 하위 검사
18개가 통과했다. 빠른 연결 개선에서는 FSM·모델 요청 펄스·차선 유도 전환
검사 125개를 추가했고, 기존 검사까지 총 2,210개와 하위 검사 18개가 통과했다.
완전 체결 56개와 기존 ATC 동작 비교, 실제 ADRV 전달 검사도 함께 통과했다.
현재 스키마 4개를 C++로 다시 생성하고 생성된 log 스키마의
구문 검사도 통과했다. 테스트 환경에서 없는 Params/IPC 인프라는
대체했으며, FSM·Cap'n Proto·CAN 패킹/파싱과 기존 C 안전 훅은 실제 코드를
사용했다. 모델 추론이나 실시간 IPC 스케줄을 검증한 결과는 아니다.
전체 차량 빌드와 사용자 EV6의 실제 차선변경·깜빡이 유지는 미검증이다.

원본 커밋의 개선 근거는 기존 주행 로그의 사후 open-loop replay에서
추가 입력 4개가 예약됐다는 보고다. 사용자 차량에서의 성공률이나 안전을
증명하는 결과로 해석하지 않는다. 적용 시 새 스키마와 관련 모듈을 함께
갱신해야 한다.
