# 새 레버 입력으로 이어가는 차선변경

기준 브랜치는 `Babysurfer-cyber/openpilot:ms-xy-radar3`의 `30ecfc1`이다.
joongyu01의 공개 개발 브랜치 보관본
[`archive/carrot-wip-dev-20261016`](https://github.com/joongyu01/openpilot/tree/archive/carrot-wip-dev-20261016)
(`765a5fd`)에서
[`05a2653`](https://github.com/joongyu01/openpilot/commit/05a2653097b8822cd5ee81be808ef58340a063db)
의 연속 요청 방식을 현재 C3 기반 구조에 맞춰 이식했다.

## 운전자 동작

- 기존 원터치 자동차선변경을 시작한다.
- 차가 차선 경계를 넘은 뒤 같은 방향 레버를 다시 툭 치면 다음 변경을
  하나 예약한다. 현재 변경이 완료된 뒤 다음 차선 조건을 다시 검사한다.
- 램프가 계속 켜져 있어도 새 레버 입력은 별도로 인식한다. 새 입력 없이
  남은 깜빡임만으로 다음 자동 변경을 계속 반복하지 않는다.
- 세 번째 변경도 해당 변경의 경계를 넘은 뒤 새 입력이 있어야 예약된다.
- 별도 설정을 추가하지 않는다. 기존 `LaneChangeNeedTorque`,
  `LaneChangeBsd`, `LaneLineCheck`, `LaneChangeDelay` 설정을 사용한다.
  특히 토크 필요 설정이 1이면 다음 변경에도 토크 확인이 필요하다.

경계 통과는 모델 차선으로 추정한다. 변경 방향의 내부 차선이 차 중심에
1m 미만으로 접근했다가, 모델이 새 차선으로 번호를 바꾸며 최근접 거리보다
1.5m 이상 멀어지는 것을 본다. 양쪽 내부 차선의 유한값·순서·폭도 검사한다.
모델에서 이 통과를 확인하지 못하면 마무리 단계 0.3초 이후의 새 입력만
예약한다. 이는 실측 위치를 보장하는 검출기가 아니다.

입력의 기준은 **레버를 누른 시점**이다. 경계를 넘기 전에 누르고 넘은 뒤
놓은 동작은 다음 요청으로 승격하지 않는다. 레버가 완전 체결되면 원터치
예약으로 취급하지 않는다. 모델 프레임 사이에 누르고 놓은 짧은 입력도
실제 레버 카운터가 정상 증가했다면 인식한다.

## 현재 브랜치에 맞춘 처리

`CarState`의 기존 UInt8 레버 카운터를 사용한다. 최초 표본은 기준값으로
저장하고, 한 방향의 정상 단일 증가만 새 입력으로 받는다. `255→0`은
정상 wrap이며, 점프·리셋·양쪽 동시 증가·무효 CAN은 이전 입력을 재생하지
않는다. 이때 아직 확정되지 않은 입력도 폐기한다.

예약은 현재 변경을 즉시 끝내거나 모델의 변경 확률·블렌딩 시간을 단축하지
않는다. 현재 변경이 완료되면 기존 `preLaneChange` 경로에서 최신 차선 폭,
도로 가장자리, 차선 종류, BSD와 측면 레이더 객체, 사용자 토크 설정을
다시 판단한다. BSD의 기존 1초 유지와 기존 수동/ATC 예외도 유지한다.
실제 같은 방향 깜빡이 피드백이 있어야 예약한 변경을 시작한다.

첫 변경 완료 후 예약이 막힌 채 대기하는 시간은 최대 약 4초다. 만료되면
HOLD와 예약을 해제한다. 나중에 BSD가 풀리거나 램프가 다시 켜져도 자동으로
재시작하지 않는다. 새 입력은 새 요청이 된다. 반대 입력·비상등·완전 체결·
반대 토크·횡제어 비활성·무효 입력·기존 변경 시간 제한에서도 예약을 버린다.

### 방향지시등 전달

- `ModelDataV2.MetaData`에 `laneChangeBlinkerHold @20`을 추가했다.
  기본값은 `none`이며 기존 필드 번호는 유지한다.
- 실제 `modeld`의 `DesireHelper.update` 결과를 이 필드로 발행한다.
- Hyundai의 기존 CAMERA SCC ADRV `0x1EA` 생성 경로에서 예약 방향을
  기존 유지 신호보다 우선한다. 좌우 HOLD를 동시에 켜지 않는다.
- 예약을 소비해 새 변경을 시작할 때도 새 변경의 경계 통과까지 HOLD를
  이어 초기 모델 확률 상승 구간에서 유지 신호가 끊기지 않게 한다.
  이후에는 기존 변경 유지 경로를 사용한다.
- 횡제어가 꺼지거나 모델이 무효·수신 중단 상태이면 HOLD를 해제한다.

정차용 `HyundaiBlinkerTest`와 연동하지 않는다. 이 기능은 주행 중 기존
방향지시등 유지 경로를 사용하며 주차보조 ECU 진단이나 SPAS 점등 요청을
추가하지 않는다. 원본의 Bluetooth, 강제 회전, 트레일러, 별도 차량 설정,
전체 차선변경 함수는 가져오지 않았다.

## 검증 범위

실제 Cap'n Proto와 CANPacker/Parser로 레버 카운터, 좌우 모델 차선,
FSM의 예약·완료·만료·취소, 사용자 조건 재검사, ADRV 출력과 직렬화를
검증한다. 기존 ATC 동작은 이식 전 helper와 같은 입력으로 비교한다.
신규 검사 126개를 포함한 관련 회귀 검사 2,029개와 하위 검사 18개가
통과했다. 현재 스키마 4개를 C++로 다시 생성하고 생성된 log 스키마의
구문 검사도 통과했다. 테스트 환경에서 없는 Params/IPC 인프라는
대체했으며, FSM·Cap'n Proto·CAN 패킹/파싱과 기존 C 안전 훅은 실제 코드를
사용했다. 모델 추론이나 실시간 IPC 스케줄을 검증한 결과는 아니다.
전체 차량 빌드와 사용자 EV6의 실제 차선변경·깜빡이 유지는 미검증이다.

원본 커밋의 개선 근거는 기존 주행 로그의 사후 open-loop replay에서
추가 입력 4개가 예약됐다는 보고다. 사용자 차량에서의 성공률이나 안전을
증명하는 결과로 해석하지 않는다. 적용 시 새 스키마와 관련 모듈을 함께
갱신해야 한다.
