# 원복 후 단일 원터치 차선변경

기준은 사용자가 연속 차선변경 기능을 원복한 `d17443b`다. 현재 경로는
단일 원터치 기반이며 삭제한 다음 차로 관측기·연속 예약·모델 HOLD 필드를
다시 추가하지 않았다.

## 차선변경 시작 시 예외

모델 스키마에서 `laneChangeBlinkerHold`를 삭제하고 발행도 중단했지만,
`LateralPlanner`의 예약 인계 분기가 여전히 이 필드를 읽고 있었다.
차선변경 준비 상태와 `desire=none`에서 실제 현재 스키마로 다음 오류가 재현됐다.

`AttributeError: struct has no such member; name = laneChangeBlinkerHold`

해당 예약 분기만 제거했다. 일반 모델/ATC 요청은 기존처럼 차선 혼합값0,
일반 `none`은1을 사용한다. 누락 필드를 예외 처리로 숨기거나 삭제한 기능을
다시 켜는 방식이 아니다.

`plannerd`는 같은 루프에서 횡방향 update/publish 후 종방향 update/publish를
실행한다. 첫 계산의 예외는 종방향 계획 발행까지 끊을 수 있다. 조향은 설정에
따라 모델의 desiredCurvature를 직접 사용하는 경로가 있어, 조향이 유지되면서
종방향 계획이 중단되는 증상과 구조상 부합한다. 실제 발생 구간 로그는 아직
받지 않아 해당 주행의 traceback까지 확인한 것은 아니다.

## 단일 원터치 처리

- 관측한 레버1을 중립0으로 놓았을 때 한 번 확정한다. 1단을 오래 잡고 있다는
  이유로 레버 해제 전에 자동차선변경을 시작하지 않는다.
- 완료 시 원터치를 소비하고 해제한다. 완료 당시 램프가 꺼졌거나 이후 램프만
  다시 켜져도 이전 타이머가 같은 요청을 재무장하지 않는다.
- 완료 이후 새로 관측한 레버 입력은 새 단일 요청이 된다. 진행 중 두 번째 입력을
  예약해 다음 차로로 넘기는 기능은 현재 없다.
- 완전 체결2는 자동 차선변경을 시작·계속하지 않는다. 기존 저속 턴의 분류와
  출력 조건은 유지한다. 고속 턴 유도 동작을 새로 추가하지 않는다.
- CAN·횡제어 오류나 취소로 끝난 입력은 해제/복구만으로 다시 사용하지 않는다.
- 기존 BSD·차선·조향 토크·지연 설정과 내비게이션 ATC 경로는 유지한다.

레버1을 모델이 한 번도 관측하지 못한 매우 짧은 입력을 카운터만으로 되살리는
보완도 원복 상태로 남아 있다. 현재 단일 입력 검사에서는 관측한1→0을 사용한다.

## 차량 표시와 깜빡이 유지

원복한 raw desire 및 모델 확률 `>0.9` 기반 방식을 유지한다. 삭제한 HOLD
메타데이터를 다시 읽지 않는다. 다만 모델 valid/alive 정보를 차량 송신부에
전달하고, 횡제어·모델·CAN이 무효이거나 레버가 완전 체결됐을 때 남은 ALC
유지 명령과 표시를 해제한다. 턴1/2와 ALC3/4는 구분한다.
종료 표시0도 매번 기록해 복사한 순정 ALC 표시가 남지 않도록 한다.
기존 끼어들기 표시와 정차 HDA 보호 조건은 유지했다.

## 검증 범위

현재 스키마의 실제 Python 코드와 Cap'n Proto/CANPacker/CANParser로 검사했다.
신규90개(횡방향 메타데이터32, 단일 원터치28, 차량 표시30)를 포함한
선택 회귀 검사1,226개가 통과했다. 원복된 기능 전용9개 테스트 모듈은
삭제된 스키마 필드가 없는 동안 명시적으로 건너뛰며, 본문과 예전 기대값을
지우지 않았다. 원복한 기능을 테스트 때문에 복구하지 않는다.

기존 펌웨어 응답 검사는 로컬에 hypothesis가 없어 이번 묶음에 포함하지 않았다.
없는 Params/IPC 네이티브 인프라는 외부 호스트 실행기로 보완했다.
장치 전체 빌드와 실제 EV6 주행 검증은 하지 않았다. 장치에서 모델·계획·차량
송신 프로세스가 현재 버전을 함께 로드하도록 업데이트 후 재부팅해야 한다.
